# 项目管理型 AI 工具箱需求文档

## 1. 文档信息

- 文档名称：项目管理型 AI 工具箱需求文档
- 目标版本：v0.2.0
- 当前基础版本：v0.1.0 Beta
- 文档状态：草案
- 维护目录：`requirement/`

## 2. 背景

当前版本已经具备项目工作区、API 测试、Git 助手、AI 代码解释、AI 代码生成、AI 历史中心、Prompt 模板、多模型配置和本地数据维护能力。

现有产品形态仍以“工具集合”为主：用户进入应用后通常先选择一个工具，再把代码、接口、Git diff 或需求文本输入到该工具中处理。项目虽然已经作为数据归属存在，但还不是主工作流的核心入口。

第二版本的大方向是把产品从普通 AI 工具箱升级为能够管理项目的工具箱。用户应先选择或创建项目，再围绕项目推进需求、任务、代码审查、接口管理、Git 变更、AI 历史和项目知识沉淀。

## 3. 产品定位

目标定位：

```text
CodexBox v0.2.0 = 项目管理 + AI 辅助开发 + 本地开发资产管理
```

核心变化：

- 从“按工具使用”转为“按项目工作”。
- 从“处理单次输入”转为“沉淀项目上下文和开发过程”。
- 从“AI 代码生成工具”转为“AI 项目推进助手”。
- 从“本地辅助工具集合”转为“本地优先的项目管理工作台”。

## 4. 目标

v0.2.0 需要达成以下目标：

- 项目成为应用的一级工作对象。
- 用户可以在应用内维护项目资料、任务、需求、Bug、优化项和开发记录。
- AI 能基于当前项目、当前任务、Git diff、API 集合和历史上下文生成更贴近项目的输出。
- Git、API、AI 历史和 Prompt 模板按项目聚合，减少工具之间的割裂感。
- 保持本地优先，不引入云端账号体系或多人协同依赖。

## 5. 范围

### 5.1 范围内

- 项目仪表盘。
- 项目资料管理。
- 项目任务管理。
- 项目级 AI 开发助手。
- AI 代码审查。
- Git 工作流项目化增强。
- API 管理项目化增强。
- 项目知识库基础能力。
- 项目数据包导入导出增强。

### 5.2 范围外

- 云端同步。
- 多人协作。
- 企业权限体系。
- 在线项目管理平台双向同步。
- 自动直接修改源码并提交。
- 内置模型服务。

## 6. 用户角色

### 6.1 个人开发者

关注点：

- 快速管理多个本地项目。
- 记录需求、Bug 和优化项。
- 用 AI 辅助理解代码、生成方案、审查 diff 和整理提交说明。

### 6.2 独立项目维护者

关注点：

- 保留项目上下文和开发记录。
- 在发布前检查 Git 变更、API 变更和 AI 审查结果。
- 复用历史 Prompt 和解决方案。

### 6.3 小型团队技术负责人

关注点：

- 用本地项目资料沉淀项目结构、技术栈、运行方式和接口说明。
- 生成需求拆解、开发计划、代码审查意见和 PR 描述草稿。

## 7. 核心信息架构

主导航建议从工具导航调整为项目导航：

```text
项目总览
项目任务
AI 开发
代码审查
API 管理
Git 工作流
项目知识库
工具箱
项目设置
```

通用工具如 JSON 工具可以保留，但建议放入“工具箱”分组，不再作为主线入口。

## 8. 功能需求

### R1 项目仪表盘

需求描述：

用户打开项目后，应首先看到该项目的总览信息和最近工作状态。

功能要求：

- 展示项目名称、路径、标签、描述、最近打开时间。
- 展示技术栈摘要，例如 Vue、Electron、TypeScript、Node.js、SQLite。
- 展示 Git 状态摘要，例如当前分支、未提交文件数、暂存文件数、最近提交。
- 展示项目任务统计，例如待处理、进行中、已完成、已归档。
- 展示 API 资产统计，例如请求集合数、环境变量数、最近请求时间。
- 展示 AI 活动统计，例如最近 AI 任务、收藏历史、常用模板。
- 提供快捷入口：新建任务、AI 生成方案、代码审查、打开 API 管理、打开 Git 工作流。

验收标准：

- 未选择项目时，页面提示创建或选择项目。
- 选择项目后，仪表盘能聚合当前项目的 Git、API、AI 和任务数据。
- 项目不存在或路径失效时，页面给出明确状态，而不是静默失败。

优先级：高

### R2 项目资料管理

需求描述：

项目资料应从简单的名称、路径和标签扩展为可管理项目运行和维护信息的资料页。

功能要求：

- 维护项目名称、路径、描述、标签。
- 维护项目类型，例如前端、后端、桌面应用、脚本工具、全栈项目。
- 维护技术栈信息，可手动编辑，也可由项目扫描生成草稿。
- 维护常用命令，例如安装、开发启动、测试、构建、打包。
- 维护重要目录说明，例如 `src/`、`electron/`、`tests/`、`docs/`。
- 维护项目备注，例如环境要求、启动注意事项、发布说明入口。

验收标准：

- 项目资料保存后可在项目仪表盘和 AI 上下文中使用。
- 手动编辑内容优先级高于自动扫描结果。
- 删除项目资料记录不会删除本地源码目录。

优先级：高

### R3 项目任务管理

需求描述：

应用需要支持在项目内管理需求、Bug、优化项和技术任务，形成 AI 辅助开发的任务入口。

功能要求：

- 支持创建任务。
- 任务类型包括需求、Bug、优化、重构、文档、发布。
- 任务状态包括待处理、进行中、待验证、已完成、已归档。
- 任务字段包括标题、描述、类型、优先级、状态、关联项目、创建时间、更新时间。
- 支持任务列表筛选、搜索和排序。
- 支持任务详情页展示任务描述、AI 输出、关联 Git 记录、关联 API 请求和历史备注。
- 支持从任务发起 AI 生成开发方案、测试建议、提交说明和代码审查清单。

验收标准：

- 每个任务必须归属于一个项目。
- 任务状态切换后能即时反映在项目仪表盘统计中。
- 从任务发起的 AI 历史必须保留任务归属。

优先级：高

### R4 项目级 AI 开发助手

需求描述：

AI 开发助手不再只处理孤立文本，而是基于当前项目和当前任务生成输出。

功能要求：

- 支持选择当前项目和可选任务。
- 支持生成开发方案，输出目标、涉及文件、实现步骤、风险点和验收建议。
- 支持生成测试建议，输出测试范围、关键用例、边界条件和回归点。
- 支持生成实现草稿，保留为 Markdown 和代码块形式，不直接覆盖源码。
- 支持引用项目资料、任务描述、Git diff、API 集合和 AI 历史摘要作为上下文。
- AI 输出写入历史时记录项目 ID、任务 ID、模型、Prompt、输出和创建时间。

验收标准：

- 未配置 API Key 时，页面显示清晰引导，不影响任务查看。
- 生成结果必须能回到任务详情和 AI 历史中心查看。
- 同一任务可以多次生成不同方案，并保留时间线。

优先级：高

### R5 AI 代码审查

需求描述：

用户应能够对当前项目的 Git diff、指定文件或粘贴代码进行 AI 审查。

功能要求：

- 支持审查当前项目未提交 diff。
- 支持审查 staged diff。
- 支持审查指定文件内容。
- 输出问题清单、风险等级、影响说明、修改建议和测试建议。
- 支持一键生成审查摘要，供提交或 PR 描述使用。
- 审查结果写入 AI 历史，并可关联到项目任务。

验收标准：

- Git 路径无效或当前项目不是 Git 仓库时，给出明确提示。
- 大 diff 应提示用户拆分或选择文件范围。
- 审查输出必须使用 Markdown 渲染，并支持复制。

优先级：高

### R6 Git 工作流项目化增强

需求描述：

Git 助手需要从通用 Git 面板升级为项目开发流程的一部分。

功能要求：

- 默认使用当前项目路径作为 Git 工作目录。
- 展示当前项目分支、状态、最近提交和变更文件。
- 支持根据 staged diff 生成 commit message。
- 支持根据当前任务和 diff 生成变更摘要。
- 支持生成 PR 描述草稿，包含背景、变更点、测试说明和风险。
- 支持把 Git 分析结果关联到项目任务。

验收标准：

- 切换项目后 Git 面板自动切换上下文。
- 生成 commit message 时不会自动执行提交。
- Git 操作失败时展示具体命令和错误原因。

优先级：高

### R7 API 管理项目化增强

需求描述：

API 测试器需要成为项目 API 资产管理入口，而不只是请求发送工具。

功能要求：

- 当前项目下展示 API 请求集合、环境变量、请求历史和 OpenAPI 导入结果。
- 支持从项目扫描结果生成接口草稿。
- 支持对 API 响应进行 AI 分析，输出字段解释、异常原因和调试建议。
- 支持从 API 请求生成测试用例建议。
- 支持把 API 请求或响应分析关联到项目任务。

验收标准：

- API 数据必须按项目隔离。
- 导入或扫描产生的 API 应保留来源信息。
- 相对 URL 继续支持 `{{baseUrl}}` 占位符。

优先级：中

### R8 项目知识库基础能力

需求描述：

项目知识库用于沉淀项目资料、AI 历史、API 说明、任务记录和重要文档摘要。

功能要求：

- 展示项目资料、任务、AI 历史、API 记录的统一搜索入口。
- 支持按类型筛选：任务、AI 历史、API、Prompt、项目备注。
- 支持收藏重要 AI 输出或任务记录。
- 支持从 AI 历史沉淀为项目知识条目。
- 支持后续扩展 README、Markdown 文档和代码结构摘要。

验收标准：

- 搜索结果必须限定在当前项目内。
- 知识条目能回溯到来源记录。
- 删除来源记录时，不应造成知识库页面崩溃。

优先级：中

### R9 项目数据包增强

需求描述：

项目数据包需要覆盖更多项目管理信息，方便迁移和备份。

功能要求：

- 导出项目资料、项目任务、AI 历史、Prompt 模板、API 请求集合和项目知识条目。
- 导入前展示预览数量和冲突信息。
- 冲突策略支持覆盖、跳过、另存新项目。
- 导入后显示导入明细。

验收标准：

- 导出包不包含 API Key。
- 导入失败时给出明确错误，不破坏已有项目数据。
- 旧版本项目包仍能导入基础项目、AI 历史和 API 数据。

优先级：中

### R10 工具箱分组调整

需求描述：

通用工具仍需保留，但应从主流程中降级为辅助入口。

功能要求：

- 新增“工具箱”分组。
- JSON 工具放入工具箱分组。
- 后续可在工具箱中扩展 Base64、时间戳、正则、URL 编码等轻量工具。
- 工具箱能力可以从项目任务或 API 调试中被调用，但不强制绑定项目。

验收标准：

- 现有 JSON 工具功能不回退。
- 主导航能清晰体现项目管理主线。
- 通用工具不干扰项目仪表盘和项目任务流。

优先级：低

## 10. 交互原则

- 项目优先：所有主流程默认围绕当前项目展开。
- 本地优先：不依赖云端账号或远程同步。
- 可追溯：AI 输出应能追溯到项目、任务、Prompt、模型和输入上下文。
- 不自动改代码：AI 可以生成方案和草稿，但不应在该阶段直接写入源码。
- 低打扰：项目路径失效、无 Git 仓库、无 API Key 等状态应给出明确提示，但不阻塞其他功能。

## 11. 里程碑建议

### M1 项目管理基础

- 完成项目仪表盘。
- 完成项目资料扩展。
- 完成项目任务管理。
- 完成项目级统计。

### M2 AI 与任务打通

- 项目任务支持发起 AI 开发方案。
- AI 历史记录项目 ID 和任务 ID。
- AI 输出可回到任务详情查看。

### M3 Git 与代码审查增强

- 完成 AI 代码审查。
- Git 助手默认绑定当前项目。
- 支持生成 commit message 和 PR 描述草稿。

### M4 API 与知识库增强

- API 管理按项目聚合。
- API 响应 AI 分析关联任务。
- 项目知识库具备基础搜索和来源追溯。

### M5 数据包与导航收口

- 项目数据包覆盖任务和知识库。
- 主导航调整为项目管理结构。
- 通用工具归入工具箱分组。

## 12. 验收标准

v0.2.0 整体完成时，应满足：

- 用户可以创建项目并进入项目仪表盘。
- 用户可以维护项目资料和项目任务。
- 用户可以从任务发起 AI 生成开发方案。
- 用户可以对当前项目 Git diff 发起 AI 代码审查。
- 用户可以基于 staged diff 生成 commit message。
- AI 历史能按项目和任务筛选。
- API 请求集合继续按项目隔离，并能关联任务或 AI 分析。
- 项目数据包能导出和导入项目资料、任务、AI 历史和 API 数据。
- 所有新增主流程具备清晰的空状态、错误状态和无 API Key 状态。

## 13. 验证建议

开发完成后建议至少执行：

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

涉及 Vue 单文件组件的大幅改造时，应额外对修改过的 `.vue` 文件执行单文件解析检查，避免模板结构错误。
