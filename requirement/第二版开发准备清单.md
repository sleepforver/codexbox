# 第二版开发准备清单

## 1. 目标

第二版开发目标是把当前应用从“普通 AI 工具箱”升级为“项目管理型 AI 工具箱”。

本清单用于把 `项目管理型AI工具箱需求文档.md` 中的产品需求拆解为可执行的工程准备事项，作为后续分阶段开发的入口。

## 2. 当前基础能力

当前代码已经具备以下可复用基础：

- 项目工作区：`workspace_projects` 表、项目列表、新增、删除、最近打开。
- 项目级数据归属：AI 历史和 API 请求集合已经支持 `project_id`。
- API 管理基础：环境变量、请求历史、保存请求、OpenAPI 导入、项目 API 扫描。
- Git 助手基础：状态、日志、diff、文件暂存、提交消息生成。
- AI 工作流基础：解释代码、生成代码、流式输出、Markdown 渲染、历史保存、Prompt 模板。
- 设置与数据维护：数据库信息、备份、恢复、清理、诊断导出、项目包导入导出。
- 验证链路：`typecheck`、`test`、`build`、Electron smoke、E2E readiness。

## 3. 主要差距

与第二版目标相比，当前主要差距如下：

- 项目只是数据归属，还不是主工作流入口。
- 缺少项目仪表盘，无法聚合任务、Git、API、AI 活动和项目状态。
- 缺少项目任务模型，无法管理需求、Bug、优化项、发布任务。
- AI 历史未关联任务，无法形成任务级开发时间线。
- 项目资料字段较少，无法记录技术栈、运行命令、重要目录和项目备注。
- 代码审查仍依附于 Git 助手，缺少独立的 AI Review 工作流。
- 项目知识库尚未建模。
- 项目包导入导出只覆盖项目、AI 历史和 API 请求，未覆盖任务和知识条目。
- 主导航仍是工具导航，项目管理主线不够明确。

## 5. 分阶段开发计划

### M1 项目管理基础

目标：

- 项目成为一级工作对象。
- 用户可以在项目内管理资料和任务。

任务：

- 扩展项目数据模型。
- 新增项目任务表和仓储。
- 新增项目仪表盘汇总接口。
- 新增项目仪表盘页面。
- 新增项目任务页面。
- 调整主导航。

验收：

- 可以创建项目、编辑资料、创建任务、切换任务状态。
- 项目仪表盘能显示项目资料、任务统计、AI 统计、API 统计和 Git 摘要。
- `npm.cmd run typecheck`、`npm.cmd test` 通过。

### M2 AI 与任务打通

目标：

- AI 输出能围绕项目任务沉淀。

任务：

- 扩展 AI 历史任务字段。
- 项目任务详情支持查看关联 AI 输出。
- AI 生成页面支持选择项目任务。
- 新增任务级 Prompt 模板或内置 Prompt。
- 生成开发方案、测试建议和提交说明草稿。

验收：

- 从任务发起 AI 生成后，结果能回到任务详情和 AI 历史中心。
- AI 历史能按项目和任务筛选。

### M3 代码审查与 Git 工作流

目标：

- 形成提交前 AI 审查和提交说明生成闭环。

任务：

- 新增代码审查页面。
- 支持审查 unstaged diff、staged diff 和指定文件。
- Git 助手默认使用当前项目路径。
- 生成 commit message 和 PR 描述草稿。
- 审查结果可关联任务。

验收：

- 当前项目不是 Git 仓库时有明确提示。
- 大 diff 有范围提示。
- 审查输出 Markdown 渲染正常，并可复制。

### M4 API 与知识库

目标：

- API、任务、AI 历史和项目资料形成项目知识沉淀。

任务：

- API 响应分析关联任务。
- API 请求支持生成测试建议。
- 新增项目知识库表和页面。
- 支持从 AI 历史沉淀知识条目。
- 支持项目内统一搜索。

验收：

- 搜索结果限定在当前项目。
- 知识条目能追溯来源。
- 删除来源记录后页面不崩溃。

### M5 数据包与发布收口

目标：

- 项目管理型能力可迁移、可验证、可发布。

任务：

- 项目数据包覆盖任务和知识库。
- 导入预览增加任务和知识条目数量。
- 更新 README、发布说明和检查清单。
- 补充 E2E readiness 和 smoke 验证。

验收：

- 新旧项目包兼容。
- 导入失败不破坏已有数据。
- `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build` 通过。

## 6. 第一阶段建议落地顺序

建议第一阶段按以下顺序实施：

1. 数据模型：schema v9、迁移、类型定义。
2. 项目任务后端：repository、service、IPC、preload。
3. 项目仪表盘后端：聚合项目、任务、AI、API、Git 摘要。
4. 前端导航：新增项目总览和项目任务入口，保留旧页面可访问。
5. 项目任务页面：列表、筛选、创建、编辑、状态切换。
6. 项目仪表盘页面：统计卡片、最近任务、最近 AI、快捷入口。
7. 验证脚本：补充 schema、IPC、路由和关键页面入口检查。

## 7. 风险和处理方式

### 7.1 导航大改风险

风险：

主导航从工具结构调整为项目结构，可能影响现有 E2E 和用户习惯。

处理：

- 第一阶段先新增项目总览和项目任务入口。
- JSON、API、Git、AI 历史等旧入口先保留。
- 等 M5 再做最终分组收口。

### 7.2 数据迁移风险

风险：

扩展项目表和 AI 历史表会影响现有用户数据。

处理：

- 所有新增字段允许空值或有默认值。
- 新增表优先于大规模重建旧表。
- `verify-data-safety.mjs` 必须覆盖 v9 表和迁移入口。

### 7.3 AI 上下文膨胀风险

风险：

把项目资料、任务、Git diff、API 和历史全部注入 Prompt 可能导致上下文过长。

处理：

- 第一阶段只注入项目资料和任务描述。
- Git diff 和 API 响应由用户显式选择。
- 后续再做摘要和裁剪策略。

### 7.4 UI 复杂度风险

风险：

项目管理页面容易变成信息堆叠。

处理：

- 仪表盘只显示摘要和快捷入口。
- 任务详情承载时间线和关联记录。
- 保持固定高度、可滚动的 AI 输出区域。
